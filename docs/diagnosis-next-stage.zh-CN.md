# 下一阶段：验证一次有害修改的原因与修复

依据“注释 1”收敛研究目标：系统自己发现自我改进中的有害修改，提出可被否定的原因，由控制器执行干预，再检验修复。先完成一个可信的真实案例，再扩展评测。本文是实施与验收计划，不是已完成实验报告。

## 固定范围

- 对象仍为 MiniAgent；第一版仅支持答案处理中可重复执行的纯转换规则。
- “一步”指一项有稳定规则 ID 的具体修改，不等于一个文件或一轮进化。
- 固定 Meta，使用 `meta_self_update: false`；诊断机制验证后再比较 Meta 自更新。
- Meta 生成可疑修改、假设、预测、反证条件、修复和实验后的诊断；控制器固定实验类型、评分与证据记录。人工仅建立评测参考和复核结论。
- 重试类规则需要完整运行对照，不能用固定答案重放声称验证了最终任务效果。

## 当前实现核对（2026-11-28）

| 模块 | 已有能力 | 下一步缺口 |
|---|---|---|
| 修改清单 | `Rule.manifest` 记录规则 ID、源码位置、哈希与依赖；迭代日志记录文件 diff 和模型理由 | 将一次具体修改与规则 ID、预期作用及候选版本显式关联；文件 diff 不等于规则修改清单 |
| 执行记录 | `run_rules` 记录 before/after、replace/no_op/disabled；规则回执绑定任务与快照 | 验证规则实际注册并执行；无回执需区分未启用、不支持和记录缺失 |
| 干预执行器 | 枚举有效规则子集，检查依赖；重复重放；使用 Benchmark 重新评分；修复可在同输入重放 | Meta 请求目前主要是 disable、predicted_output、claim；补全明确的实验类型及反证条件，保留执行失败和不支持状态 |
| 归因与修复报告 | 记录预测支持/推翻、质量变化、修复与 Meta 决定 | 自动生成逐假设诊断表；保存 Meta 看过执行证据后的更新结论，并与控制器事实分列 |
| 新题验证 | 原流程有学习检查、新题审计、最终测试 | 尚缺统一的原版/候选/撤销/修复四版本完整运行对照 |

已有[独立规则试验](../results/rule-audit-pilot-20261128/REPORT_CN.md)支持逗号规则的局部转换解释，包含模型预测与修复。其人工案例在已知问题后构造，历史输入是代理边界，不能充当下一阶段自然案例的完整证据。今日四轮运行接纳了未注册的中间件，且没有规则重放事件，见 [README 3.6](../README.md#36-同一-miniagent-起点下的-recursive-ca-rsi-与-base2026-11-28)。这应作为“修改未生效”的开发证据，不能再次算独立测试。

## 先完成一个真实案例

1. **冻结任务与版本。** 从真实 RSI 候选保存父版本、候选、运行记录和修改清单。已有 grounded_answer 案例只用于开发；原始边界缺失时明确标记，后补执行不冒充旧运行记录。
2. **核验生效。** 保存模块注册、规则调用、任务和快照绑定、源码哈希以及规则前后答案。未生效修改进入诊断，不默认它导致分数变化。
3. **事前假设。** Meta 写出 case_id、rule_ids、怀疑的原因、实验类型、改变的因素、精确预期输出、反证条件。先落盘再执行，不能事后改预测。
4. **控制器干预。** 支持关闭单规则、单独启用、两规则组合、替换修复规则。保持输入与其他条件相同；依赖不满足或完整管线无法复现时返回证据不足。
5. **更新诊断与最小修复。** Meta 读取实验事实，明确原因得到支持、被推翻或证据不足，再给出修复。预测正确与规则有害分别判定：关闭有益规则也可能准确预测输出。
6. **四版本完整评估。** A 修改前；B 原候选；C 只撤销可疑修改且保留其余修改；D 最小修复。四组共享新验证题、模型、推理参数与预先确定的重复次数。局部规则重放结果和完整任务结果分别记录。
7. **最终测试。** 验证集决定版本后冻结选择，在未曝光测试集评测一次。预先冻结的四组可同时测试用于比较，但测试分数不反过来改变选择或修复。

数据清单必须保存 task ID、内容哈希、用途和曝光记录。与历史诊断、选择及测试中已经查看并用于调整的任务去重；这些任务转为开发用途。改变 seed 不能替代内容去重。

交付诊断表固定包含：可疑修改、问题、原因假设、预期与反证、实际干预、实验结果、Meta 更新判断、建议修复、新题修复验证、当前结论。每行关联真实记录路径与版本哈希，缺失证据留空并说明原因。

## 再开展小规模评测

受控案例先做 12 个：单条有害、两条冲突、未生效、正常无需修改各 3 个。它们是 12 个独立诊断单元，不把已有 12 条答案样例直接当作 12 个定位案例。参考标签对 Meta 隐藏。

自然案例至少 8 个：预先固定运行范围，按运行开始时间、轮次、候选 ID 排序连续收集。保留成功、失败、无明显变化及不支持的候选；报告全部收集数与排除理由。人工结合执行证据建立参考标签；参考仍不确定的案例不硬判正误，但计入证据不足比例。

| 指标 | 固定统计口径 |
|---|---|
| 定位质量 | 规则级 precision/recall、正常修改误报率；同时给 TP/FP/FN 和分母，参考不确定项单列 |
| 证据覆盖 | 有效执行干预的诊断数/全部诊断数；支持、推翻、不足分别计数，区分不支持与执行失败 |
| 修复效果 | 新题上的 D−B、D−C、D−A；逐题改正与新增退步；保留 B 相对 A 原有收益的比例 |
| 额外成本 | 诊断、干预、修复、选择、最终评估分别记录调用、输入/输出 token 与耗时，失败调用也计入 |

受控与自然案例分表报告。定位成功不自动意味着修复成功；D 优于 B 也不自动意味着优于 C。没有修复或拒绝修复的案例保留在总样本中。

## 首次验收与汇报

第一里程碑是一个真实候选的完整证据链，包含事前预测、实际干预、反例检查、模型修复、四版本新题结果和成本。结果可以失败；不能以合理解释或离线测试通过代替真实证据。

六页汇报按研究问题、方法流程、完整案例、定位结果、修复与成本、失败及下一步组织。当前可报告程序原型、受控测试和限定范围的独立规则试验；尚不能报告自然修改上的通用定位能力或递归更新收益。完成固定 Meta 的诊断机制验证后，再设计相同诊断机制下固定/自更新 Meta 的对照。
