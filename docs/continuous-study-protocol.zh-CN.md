# 连续自然候选实验协议（2026-11-28）

本次收集 10 个实际改变初始 MiniAgent 的候选，最多 20 次按顺序保存的提议。没有改动、格式无效或超出接口的提议单独记录；已经形成候选的执行失败、没有观察到错误、没有修复等情况不排除。若上限内未达到 10 个，按实际数量报告，不声称完成。

## 固定条件

- 固定 Meta 与初始 Task，不开启 Meta 自更新。候选从同一初始版本产生；Meta 可看到之前提议及训练反馈，但看不到新验证或测试。
- 模型为 DeepSeek-V4-Flash，温度 0，关闭 thinking；Target 最多 3 轮，Worker 最多 1 轮，每次最多输出 6500 token。
- Meta 直接输出 JSON 完整文件补丁，控制器应用。每阶段一次请求，不进入编辑工具循环。提示要求 agent.yaml、一个答案中间件和 main skill，最多 4 条纯规则；控制器硬性检查允许路径和最多 3 个文件，规则组合是否有效由重放检查。
- 这是针对答案处理规则的有限接口实验，不是原版 Meta-Harness 的完整端到端复现。原流程对照使用其“完整候选 EM 严格提高才采用”的选择规则。
- 从 seed 20261130 确定的 128 题池中排除已知历史曝光后，按预定顺序冻结 8/40/40。8 道训练题共享，每个候选分配不同的 4 道验证题、4 道最终测试题。

## 因果检查与修复

每个规则请求必须引用真实 case ID、规则 ID，准确复述所保存的规则前输入和完整管线输出，并给出预测、原因和反证。引用不符时拒绝执行该请求并记录。少量字符串一致性检查不能替代语义判断，Meta 文本仍可能误判。

所有可用训练边界（最多 16，本次训练题为 8）进入全部有效规则组合的控制器重放，每组合重复两次。正常、未触发和有益规则同样保留。预测输出命中且关闭后质量改善，才支持在该冻结输入上的有害原因。没有边界或不能复现时保留证据不足。

Meta 随后读取精简的实际干预结果，更新判断。只有存在得到控制器支持的有害请求时，才允许其提交修复；修复在原冻结输入上严格改善且无新退步，才进入新题选择。原始完整执行证据仍保存在本地，精简只去掉重复上下文和事件副本。

## 同候选的三种选择

| 流程 | 规则 |
|---|---|
| 原选择规则 | B 完整候选可用且新验证 EM 严格高于 A，采用 B，否则 A |
| 仅零退步门槛 | 在原选择规则上要求没有逐题退步，不诊断、不修复 |
| 增强流程 | 在 B 和经冻结输入检查合格的 D 中选择验证 EM 严格高于 A、且零退步的版本；同分优先 B；否则 A |

C 是仅撤回首个得到支持的规则请求的版本，保留其他候选文件，作为诊断和修复效果的比较，不进入选择。没有得到支持的请求时 C/D 不存在，不用人工补造。

所有选择冻结后，再评估所有已存在的 A/B/C/D 测试表现。同一个版本在同一组题上只调用一次，各选择流程共享结果；失败结果也不通过重复调用挑选好分数。测试不反馈给任何后续修复。

该设计用于比较固定候选流的选择结果，不等同于两条各自适应的演化轨迹。增强流程还改变了零退步条件，因此必须同时报告“仅门槛”组，不能将更严格拒绝候选带来的变化全部归因于诊断修复。

## 统计与限制

报告提议总数、实际候选数、可重放数、合法请求数、得到局部支持的原因、生成与通过检查的修复数。逐候选保存四版本、选择和逐题测试变化。

测试上“观测坏修改”定义为相对 A 至少新增一道错误；“观测好 B”定义为 B 严格提高 EM 且无退步。分别报告坏修改放行、好 B 被选择 A 阻挡、以及分母。它们是每候选 4 题上的观察，不是稳定的真值或广义误报率；独立人工参考复核仍须另做。

调用成本分为提议、学习评估、诊断、反思与修复、验证、最终测试。共用成本只算一次。控制器组合重放不调用模型；本次记录整段运行时间及 Meta 阶段等待时间，尚未分别计时每次局部重放；本次不能以轮数表示等算力。

同快照温度 0 仍可能有独立采样差异；局部纯规则重放的因果边界不能外推为完整运行因果效果。10 个候选用于发现问题和验证流程，不足以证明稳定有效。未支持检索、重试与规划步骤的同等完整干预。

## 执行入口

```bash
# 仅准备数据和冻结协议，不调用模型
.venv/bin/python scripts/run_continuous_diagnosis.py \
  --config configs/continuous_diagnosis_20261128.yaml \
  --output runs/continuous_diagnosis_20261128 --prepare-only

# 正式执行；同目录中断恢复复用已记录请求和评估
caffeinate -i .venv/bin/python scripts/run_continuous_diagnosis.py \
  --config configs/continuous_diagnosis_20261128.yaml \
  --output runs/continuous_diagnosis_20261128
```

完整运行完成后禁止同目录重跑。首次模型调用前冻结 driver/config 哈希，后续恢复检查一致性。已提交给模型但尚未落盘的调用仍可能无法恢复其用量，不将缺失当作零。
